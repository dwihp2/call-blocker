# A release build requests only what blocking needs

The app's privacy promise is a permission list, so the list is enforced by the build rather than described in copy. `verifyReleasePermissions` in `apps/mobile/android/app/build.gradle` reads the packaged release manifest and fails `assembleRelease` and `bundleRelease` unless it requests exactly `VIBRATE`. `apps/mobile/android/app/src/release/AndroidManifest.xml` removes what the app does not use and what the libraries bring in: `INTERNET` and `ACCESS_NETWORK_STATE` (a debug build needs them — Metro serves the bundle over the local network), `SYSTEM_ALERT_WINDOW` (React Native's development overlay), and the legacy external-storage pair (files are written through the system file picker, never to shared storage). No contacts permission appears on either side, because the app has no contacts access at all (ADR 0007). iOS has no permission list to enforce, so the equivalent surface is its usage-description strings: a release build declares none, and the Privacy screen shows that empty list.

The Privacy screen reads the list back from the platform rather than holding its own copy — Android's requested permissions from the package manager, iOS's usage reasons from the app's own `Info.plist` — so what a person sees is what the system says, not what the app claims. The alternative, a promise written in documentation, drifts the first time a dependency adds a permission; a build that refuses to produce the artifact cannot.
